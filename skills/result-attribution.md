# AgentKline 结果归因（亏损单）

## 什么时候用

用户问"这次回测为什么亏 / 这笔单怎么回事 / 帮我看看问题在哪"，或你要主动复盘一次实验时。
先确认手上是**已经跑完的结果**（`list_results`），不是还没跑的假设。

## 可用的手（工具）

| 工具 | 用途 |
|---|---|
| `list_results(board_id?, timeframe?)` | 结果清单（摘要，不含大数组） |
| `get_result(result_id, section="summary")` | 元信息 + 统计 + 数据质量 + 执行假设 + 指纹 |
| `get_result(result_id, section="trades", limit=0)` | 逐笔交易（含 entry/exit 时间与价格、pnl、reason） |
| `focus_result_trade(result_id, trade_index)` | 把用户屏幕带到第 N 笔（需已打开 Web UI，否则 NO_BROWSER） |
| `switch_board` / `switch_timeframe` | 先切到结果所在现场（focus 只对当前现场生效） |
| `set_view_range(board, tf, from, to)` | 无浏览器/要框一段时间时的退路 |

## 第 1 步：先核对，再看数

读 `summary` 后逐项确认，任何一项异常都要写进报告，不要静默跳过：

1. `status`：`completed_trades` / `open_position_only` / `no_signals`。`no_signals` 先谈信号为什么没触发，
   不要硬聊盈亏；`open_position_only` 要提醒"期末还有持仓，统计只含已平仓"。
2. `data.quality`：`verdict=bad/warn` 时先讲数据（缺口/重复/覆盖不足），再讲策略。
3. `freshness`（`list_results` 返回）：`stale=true` 表示结果基于旧快照（回补/换源/修订），
   结论要降级——"这份结果反映的是当时那份数据"。
4. `execution_assumptions`：成交规则（如次开盘）、费用/滑点、杠杆、是否做空。
   费用高或滑点大时，先排除"成本吃掉的亏损"。
5. 样本量：已平仓笔数 < 10 只做描述性观察，不下"策略失效"结论；≥ 30 才谈统计意义。

## 第 2 步：挑样本（不要只挑最惨的一笔）

从 `trades`（`limit=0`）中：

- 按 `pnl` 升序取**亏损 Top 5**（默认），并统计：亏损笔数 / 总笔数、亏损总额、最大单笔亏损；
- 按 `reason` 归类：`stop_loss` / `take_profit` / `flip`（反向翻仓）/ `end_of_backtest`（期末强平）/
  策略自定义 reason（自由文本，按字面归类，不认识的照抄）；
- 观察聚集性：同一 reason 连续出现、同一时间窗口扎堆、持仓时长异常（极短=噪音，极长=扛单），
  这些是"结构问题"的信号；单笔孤立亏损更可能是"执行/随机"。

## 第 3 步：运镜（让用户看到你说的是哪一笔）

1. 先 `switch_board` / `switch_timeframe` 到结果所在现场（`data.board` / `data.timeframe`）；
2. `focus_result_trade(result_id, trade_index)` —— 会选中结果、打开详情、选中该笔并在图上定位；
3. 报 NO_BROWSER 时不要假装成功：改用 `set_view_range(board, tf, entry_time - 若干根, exit_time + 若干根)`，
   并在报告里注明"只给了时间范围，未自动选中该笔"。

`trade_index` 与 `get_result(section=trades)` 的顺序一致（从 0 开始），先取再点，不要凭页码猜。

## 第 4 步：归因（四类，概率措辞）

对每一笔（或一组同因交易）给出一个主因，允许并列但不要全都说：

| 类别 | 典型证据 |
|---|---|
| 市场 | 进场后同向快速反向、波动放大、缺口跳空；同期基准也跌 |
| 信号 | 同一形态反复失败、参数在边界、信号滞后（金叉时已涨一段） |
| 执行 | 止损滑点、成交价偏离、费用占比高、期末强平 |
| 数据 | 缺口/重复/复权跳变、旧快照、覆盖不足 |

措辞要求：用"更可能是 / 倾向于 / 证据不足以排除"，**不要**写"因为 X 所以必然亏"。
一条交易只能有一个主因时，明确说"主因"，其余列为"同时存在"。

## 第 5 步：输出骨架（固定四段）

```markdown
**结论**：一句话（哪种问题、影响多大、是否可修）。

**证据**
- 本次 N 笔已平仓，亏损 M 笔（占比 P%），亏损合计 X，最大单笔 Y（#序号，时间）。
- 亏损集中在 reason=...（k 笔）；数据质量 verdict=...；旧快照=是/否。
- 图上位置：第 #i 笔在 <日期区间>，进出场 <价格> → <价格>。

**归因**
1. 主因：<类别> —— 依据（数字/位置）。
2. 同时存在：<类别> —— 依据。
3. 证据不足：<你没法确认的部分，明确说需要什么数据才能确认>。

**建议**
- 一条可执行的下一步（例如"把 fast/slow 从 5/20 调到 10/30 复跑同窗口对比"，
  或"先导出数据检查缺口区间再谈参数"），附验收方式（看哪个指标变化）。
```

不要输出交易流水全文；引用交易用 `#序号`，需要时再给 3 行以内的关键字段。

## 边界

- **不重算、不改结果**：结果冻结；你只读与呈现，要验证假设就再跑一次回测（产生新结果）。
- **不删结果**：清理是用户的动作。
- 不把"亏损"直接等同"策略错"：先排除数据、成本、样本量三个前提。
- stale=true 时，报告开头就要写"基于旧快照"，建议先复核数据再下结论。
- 用户没给结果时先说"还没有结果"，并给出跑一次的最小参数，不要编造数字。
