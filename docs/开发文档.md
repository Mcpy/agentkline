# AgentKline 开发文档

> 版本：v0.3.2 ｜ 面向：开发者 / 维护者 / 接入方
> 配套：`docs/API文档.md`（接口细节）

---

## 1. 项目定位

AgentKline 是一个**交互式 K 线画板 + 实时行情终端**，服务于量化团队的可视化调试：

- 多画板 × 多时间周期，数据隔离
- **全脚本化**数据源与指标（Python 脚本即插件）
- 实时轮询 + 历史回溯 + 主副图联动（时间轴/十字光标）
- 同一核心同时暴露 **Web（FastAPI）** 与 **MCP** 两种接入方式

## 2. 总体架构

```
                 ┌──────────────────────────────┐
                 │      core/service.py         │  ← 业务核心（可编程，无传输依赖）
                 │  AgentKlineService           │
                 │   ├─ state (内存状态)         │
                 │   ├─ script_engine (脚本执行) │
                 │   └─ datasource (轮询/合并)   │
                 └──────────┬───────────────────┘
              notify(推送)  │            ▲ 直接调用
        ┌───────────────────┤            ├──────────────────┐
        ▼                   ▼                             ▼
┌────────────────┐  ┌─────────────────┐          ┌─────────────────┐
│ api/web_app.py │  │ api/agent_app.py│          │  (未来其他壳)    │
│ web 端口(无鉴权)│  │ agent 端口(全鉴权)│         └─────────────────┘
│ 页面+WS+用户操作│  │ REST 全量 + /mcp │
└────────────────┘  └─────────────────┘
       ▼
┌───────────────┐
│ frontend/ → web_dist │  Vite 模块化前端（构建后由 web 端口服务）
└───────────────┘
```

**核心思想**：业务逻辑全部在 `core/service.py`，web/agent 两个 FastAPI 薄壳与 MCP
只是把 service 的返回值包装成 HTTP/WS 或 MCP 协议。两端口**同进程共享同一 service
实例**（`api/common.py`），推送经 `service.notify` → WS 直达浏览器。路由按组注册
（`api/routes.py`），web 只挂"页面+WS+只读+用户交互写"，agent 挂"只读+执行+/mcp"。

**v0.4 模型四支柱**：
1. **一切皆脚本**：K 线真相层=可重放配方（script id + params），push/load_csv 永久出局；
   脚本双根（builtin 只读 / custom 可写），id=kind/name，字面元数据族 ast 静态抽取。
2. **一标的一板**：board.source_lock={script, identity 快照}，建板即锁不可变；
   换标的/换源=新现场；撞锁 SOURCE_LOCKED+结构化 suggestion 一键改道。
3. **指标实例**：登记处(board)+物化缓存(tf)；inst_id 把手；recipe(随K线重算)/blob(冻结) 两血统。
4. **WS 标准信封**：{v,type,seq,ts,payload} 硬切；ohlcv_update 差量化；init/switch 携带窗口非全树。

## 4. 后端模块说明（v0.4）

### 4.1 core/state.py — StateManager
- 层级：`boards[id] → {source_lock, ind_registry} + timeframes[tf] → {ohlcv, markers, ind_cache, subplots, drawings}`
- 纯内存，**重启丢失**（持久化在规划池：JSON 名册落盘，只存配置不存 bar）
- 指标三本户口已收敛：登记处 `ind_registry`（inst_id→instance）+ 物化缓存 `ind_cache`（inst_id→values/lines/markers）
- `set_ohlcv` 挂 R8 护栏：>max_bars_per_slot 截最旧 + dropped 回报

### 4.2 core/script_engine.py — ScriptEngine
- 双根解析 custom→builtin（shadow 时 list 带 source）；id=kind/name 硬切
- ast 静态抽取 NAME/DESC/PARAMS/CAPS/IDENTITY + mtime 缓存（列目录零 exec）
- CAPS 一致性校验（CAPS_MISMATCH）；`list_symbols(ref,q)` 门控 CAPS.symbols
- `save_script(id,code)` 只写 custom、保存即校验；L1 沙箱=exec 隔离命名空间（自律）

### 4.3 core/datasource.py — DataSourceManager
- 槽配置纯配置化 `{script,params,mode,poll_s}`；运行态 status 分家（last_error/last_fetch/next_due）
- 轮询循环每轮动态读 poll_s（改即生效不重启不碰数据）；stop_sync 供同步路径
- **K 线合并**（`_merge_ohlcv`）：保留更早历史 + 新窗口；连续 3 次失败推 datasource_error
- 重算委托 service.recompute_indicators（尾窗 max_window）

### 4.4 core/service.py — AgentKlineService
- 业务全操作；板锁逻辑（_lock_board/_locked_err）、set_kline_source 声明式幂等、backfill、
  指标实例 CRUD、search_symbols（索引 TTL 日级）、save_script 包装（+scripts_changed 广播）
- 广播差量化 `bc_ohlcv_delta`（prepended/appended/updated）；init/switch 窗口化 get_state_windowed
- 操作成功后 `self.notify(msg)` → WS 信封广播（先写状态后广播）

## 5. 关键数据流（v0.4）

### 5.1 实时刷新（轮询）
```
datasource 轮询(动态 poll_s) → run_script → _merge_ohlcv(保留历史) → set_ohlcv
  → recompute_indicators(recipe 实例尾窗重算)
  → bc_ohlcv_delta(差量) + indicator_update → WS 信封 → 前端按 ts 合并原地更新
```

### 5.2 历史回溯（向左平移）
```
前端视口 from<=2 且 _userTouched(真手势) → POST /backfill → run_script(until=earliest)
  → 前插 older + shift_blob_caches(blob 头部补 None) → bc_ohlcv_delta(prepended)
  → 前端视口右移 N，保持看到原K线；CAPS.backfill 无徽章=NO_BACKFILL 直接停
```

### 5.3 前端原地更新（不重置视口）
- 实时更新不重建图表，只 `series.setData`/差量合并；data-info 统计实时刷新
- 视口策略：在右缘→跟随新K线；缩放/左移中→保持视口；历史前插→右移 N
- 程序化渲染（init/切板/刷新）置 _programmaticRange + _userTouched 门，杜绝误补历史

## 5.4.1 前端模块调用纪律（v0.4.2 老 bug1 教训）

- WS handler / 乐观更新路径的**首行旁路调用**（refreshSearch 这类顺手刷新）是静默断链高发位：
  漏 import 即 ReferenceError 断整条 handler，且无日志（uncaught 于事件回调）——v0.4.1 曾双路径同刻断致删板残影回归。
- 纪律：handler 首行旁路调用必须 try/catch 降级或入 e2e 活体链；新增跨模块调用时 grep import 表对齐。

## 5.5 性能机制（v0.4.1）

- K线：每槽一条 **daemon 轮询线程**（v0.4.3 自 asyncio task+executor 换型——该链两度不可解释挂起；
  线程模型有 watchlist Timer 先例稳定）；`effective_poll_s` 可见性分级（view 命中=poll_s，其余 60/120/300s）；
  sleep=**可中断 Event.wait**：`poke`（switch_timeframe 与 **report_view 命中**）force+set 唤醒长睡 loop
  （bug5 长睡陷阱根治：建板/重连后 view 上报到达前 loop 已按降频档入睡，不唤醒则新板价格冻至多 5 分钟）；
  gap 探针：周期空窗>3×eff+15s 或 fetch>8s → warning 入日志。
- 雷达：按源批量 `tickers()`（无则回退逐行）；可见行用 bar close 合成 quote 去重；
  Timer 线程广播经 `MAIN_LOOP + run_coroutine_threadsafe` 投递（他线程广播契约：fail-loud 不静默）。
- 前端：零轮询；WS 信封差量；抽屉开闭 K 线经 ResizeObserver 自适应。

## 6. 前端设计（Vite 模块化，v0.3 已完成工程化）

前端源码在 `frontend/src/`，Vite 构建到 `web_dist/`，由 FastAPI 服务（`/` + `/assets`）。
**无回退**：未构建时 `/` 返回 503 提示先 `npm run build`。模块划分（依赖无环）：

| 模块 | 职责 |
|------|------|
| `lwc.js` | `import * as LightweightCharts`（npm v5.0.0）再导出 |
| `state.js` | 全局 `state` 对象 |
| `format.js` | `formatTimeCN` / `isIntraday` |
| `log.js` | 日志、`toggleLog` |
| `ui.js` | 画板/周期 tab、切换、周期"+"菜单（interval_options）、板右键菜单（身份证卡/删除） |
| `render.js` | 建图/指标/划线/成交量/十字标同步(真悬停源判定)/视图上报/铭牌继任者(引导页/身份证卡)/data-info 实时 |
| `search.js` | 标的搜索弹层：行=二元组+●徽标、@源名高级输入、点行建板即锁、撞锁 toast 一键改道 |
| `settings.js` | 指标设置弹窗（inst_id + PUT 声明式） |
| `watchlist.js` | v0.4.1 雷达抽屉：quotes_update 驱动/行点击切现场或一步建板/三态点+未读角标 |
| `menu.js` / `draw_interact.js` | 右键菜单 / 划线鼠标交互 |
| `ws.js` | WebSocket 信封解析({v,type,seq,ts,payload})、差量合并、消息分发、`applyState` |
| `main.js` | 入口：绑定事件（含搜索/弹层）+ 连接 WS |

依赖方向：`state/format/lwc/log ← search ← render ← ui ← ws ← main`（无环）。
v0.4 前端关键门：手势门 `_userTouched`（程序化渲染不补历史）、防误载标志 `_programmaticRange`、
视口恢复仅在前插/追加时执行（原地 tick 不动视口，防蠕变）。

构建：`cd frontend && npm install && npm run build`。
（注意：构建依赖 devDependencies，请勿在 install 时设置 `NODE_ENV=production`；
网络受限时可临时指定镜像 `--registry=https://registry.npmmirror.com`。）

关键机制（与单文件版一致，仅组织变化）：

| 机制 | 实现 |
|------|------|
| 时间轴联动 | `subscribeVisibleLogicalRangeChange` 互相同步主副图 |
| 十字光标联动 | `subscribeCrosshairMove` + `setCrosshairPosition`（垂直同时刻，水平各自值） |
| 实时不重置 | `applyDataUpdate` 原地更新 + 视口保持/跟随 |
| 历史加载 | 视口左缘(用户手动)触发 `loadMoreHistory`；程序化视口打标不触发 |
| 默认视口 | `showLatest(200)` 右对齐最新 200 根，非全量 |
| 指标显隐 | 指标栏 chip 点击 toggle；副图全隐藏→折叠释放空间 |
| 指标无杂线 | 指标 `priceLineVisible/lastValueVisible/crosshairMarkerVisible=false` |
| 图例 | 主图 OHLC+涨跌 / 成交量 / 副图指标，**一个指标一行**（行内多值横排），行数超限（主6/副2/量1）回退横排；随十字标更新，移开显示最新；`updateLegends()` |
| 指标层级 | `zOrdered()` 柱状先创建（垫底）、线/面积后创建（在上），防 MACD 柱遮线 |
| 指标命名 | 内部 `name` 稳定 + `display_name` 自动「根名(参数)」/可覆盖；根名优先级：run-script `display_name` > 脚本 `label()` > 脚本 `NAME` > 文件名 stem；脚本声明 `PARAMS` 默认值（合并存储，供命名+弹窗回显）；`_auto_display`/`_set_display` |
| 指标更新 | `POST /api/indicator/update/{name}`：`params`→重算、`style`→单线、`lines_style`→逐线、`display_name`→自定义、`auto_label`→恢复自动；前端 chip ⚙ 设置弹窗 |
| 时间格式 | 中国习惯；日线只显示日期，日内显示日期+时间 |
| 去 logo | `layout.attributionLogo=false` |
| 用户划线 | 左侧工具栏 水平线/趋势线；两点锚点+虚线预览；双击选中/拖动/端点/右键菜单；`draw_interact.js`；划线为图表原生对象（可被截图） |
| 划线默认样式 | 每工具默认(color/lineStyle/lineWidth)存 localStorage；预览辅助线继承默认；改样式保存后成为该类型新默认（TV 式） |
| 最新价标签 | 自绘 `.last-price-label` 始终显示最新收盘(涨绿跌红)，越界吸附价格轴顶▲/底▼；`updateLastPriceLabel()`，渲染/视口/数据更新后 + rAF 复核 |
| 截图 | `captureSnapshot()` 用 takeScreenshot 拼接 主图+成交量+副图；`drawOverlay()` 把 DOM 图例(OHLC/指标值/VOL)+最新价标签画回 canvas；WS `snapshot_request` 触发，上传 `/api/snapshot` |
| 标记单位 | markers time 统一毫秒；`<1e11` 视为秒自动×1000（容错） |

**注意**：Lightweight Charts **不自带画图工具**，本项目用自绘叠加层+原生 series 实现画线。

## 8. MCP 设计

- 用 `mcp.server.fastmcp.FastMCP`，工具一一映射 service 方法
- **Streamable HTTP 挂载**：`api/agent_app.py` 把 `mcp` 挂到 agent 端口 `/mcp`，
  与 web 端口共享同一 service 实例（`mcp_server.service = service`），agent 操作实时推 WS
- 不再提供独立 stdio 进程（无头实例与"共用画板"目标相悖）；如后续需兼容仅 stdio
  的客户端，可再加指向本服务的 HTTP 薄代理
- 工具粒度：画板/周期/数据源/脚本/指标(含 `update_indicator`)/副图/标记/划线/状态/
  截图(`take_snapshot`/`get_snapshot`)，覆盖 AI 自动化全流程
- 截图依赖浏览器连接 `/ws`（后端不渲染）；`take_snapshot` 发 `snapshot_request`
  后轮询读取，合成图含图例+最新价标签
- 鉴权：agent 端口（含 `/mcp`）全量需 Bearer token，读+执行不区分（见 API文档 §12）；
  时间单位统一毫秒

## 9. 部署

```bash
./start.sh                 # 或 pip 安装后: agentkline
# web  : http://<host>:8765        （用户浏览器，无鉴权）
# agent: http://<host>:8766/mcp/   （AI agent，全量鉴权）
```

双端口 host/port 在 config.yaml `server.web` / `server.agent` 配置，或被
`AGENTKLINE_WEB_HOST/PORT`、`AGENTKLINE_AGENT_HOST/PORT` 覆盖。
鉴权（可选）：`AGENTKLINE_TOKEN` 或 `config.yaml auth.token`；不设置则 agent 端口仅本机可用。

路由分组（`routes.py`）：
- `register_read` 只读（两端口都有）
- `register_user_write` 用户交互写（仅 web）
- `register_manage` 删板 / 删周期 / 删改指标（**两端口都有**）
- `register_exec` 执行 / 脚本 / 数据源（仅 agent，全量鉴权）

端到端测试（打 agent 端口，需 token）：

```bash
python test_e2e.py --port 8766 --token <token>   # token 也可用环境变量 AGENTKLINE_TOKEN
```

依赖：fastapi / uvicorn / pydantic / websockets / mcp / ccxt / pyyaml（见 requirements.txt / pyproject）。

## REST wrapper 线程模型（v0.4.4 架构根治）
- 历史病：`routes._make_endpoint` 为 async wrapper **直调 sync 工具函数于 event loop** → 任一慢同步工具
  （建板首拉/索引构建）阻塞全 loop = 全局串行 choke（睡源零网络实验：建板中全 REST 拖 9s 证毕）；
- 现：sync 工具一律 `await run_in_threadpool(fn, **kwargs)`（starlette）离 loop；async 工具保持 await；
  并发请求=anyio 线程池并行（40 worker）；
- 配套：POST/PUT 也收 query 作补充源（body 优先）——修 `backfill?limit=` 被静默丢弃（e2e 双形态钉死）。

## 搜索索引生命周期（v0.4.4）
- 启动预热：lifespan 后台线程并行建全源索引（不阻塞启动）；
- 热态：内存本地过滤毫秒返回；TTL 日级过期=**stale-while-revalidate**（旧索引继续服务+后台刷新无缝换）；
- 冷态（新源）：同步并行构建每源 8s cap（`INDEX_BUILD_TIMEOUT` note）；手动 `?refresh=true` 同步=显式要新；
- `_build_index` 防重入（预热/搜索/刷新撞车不重复建）。

## 建板失败语义（v0.4.4 用户裁决）
首拉超 10s cap 或源错误 = **建板失败+原因**（SOURCE_FETCH_TIMEOUT/SOURCE_FETCH_ERROR），删板返回，不建空板；
初始槽后台线程配置（响应不等网络）。
