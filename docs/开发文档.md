# AgentKline 开发文档

> 版本：v0.3.0 ｜ 面向：开发者 / 维护者 / 接入方
> 配套：`docs/API文档.md`（接口细节）

---

## 1. 项目定位

AgentKline 是一个**交互式 K 线画板 + 实时行情终端**，服务于量化团队的可视化调试：

- 多画板 × 多时间周期，数据隔离
- **全脚本化**数据源与指标（Python 脚本即插件）
- 实时轮询 + 历史回溯 + 主副图联动（时间轴/十字光标）
- 同一核心同时暴露 **Web（FastAPI）** 与 **MCP** 两种接入方式

---

## 2. 总体架构

```
                 ┌──────────────────────────────┐
                 │      core/service.py         │  ← 业务核心（可编程，无传输依赖）
                 │  AgentKlineService           │
                 │   ├─ state (内存状态)         │
                 │   ├─ script_engine (脚本执行) │
                 │   └─ datasource (轮询/合并)   │
                 └──────────┬───────────────────┘
              notify(推送)  │            ▲ 直接调用
        ┌───────────────────┤            ├──────────────────┐
        ▼                   ▼                             ▼
┌────────────────┐  ┌─────────────────┐          ┌─────────────────┐
│ api/web_app.py │  │ api/agent_app.py│          │  (未来其他壳)    │
│ web 端口(无鉴权)│  │ agent 端口(全鉴权)│         └─────────────────┘
│ 页面+WS+用户操作│  │ REST 全量 + /mcp │
└────────────────┘  └─────────────────┘
       ▼
┌───────────────┐
│ frontend/ → web_dist │  Vite 模块化前端（构建后由 web 端口服务）
└───────────────┘
```

**核心思想**：业务逻辑全部在 `core/service.py`，web/agent 两个 FastAPI 薄壳与 MCP
只是把 service 的返回值包装成 HTTP/WS 或 MCP 协议。两端口**同进程共享同一 service
实例**（`api/common.py`），推送经 `service.notify` → WS 直达浏览器。路由按组注册
（`api/routes.py`），web 只挂"页面+WS+只读+用户交互写"，agent 挂"只读+执行+/mcp"。

## 4. 后端模块说明

### 4.1 core/state.py — StateManager
- 层级：`boards[board_id] → timeframes[tf] → {ohlcv, markers, indicators, subplots, dynamic_indicators}`
- 纯内存，**重启丢失**（v0.1 设计；持久化见路线图）
- `set_indicator` 为**合并更新**：重算指标时只覆盖非 None 字段，保住 subplot/style/script_path

### 4.2 core/script_engine.py — ScriptEngine
- `run_script(path, params)`：数据源脚本，`main(params) -> list`
- `run_indicator_script(path, ohlcv, params)`：指标脚本，`main(params, ohlcv) -> list|{lines,markers}`
- 脚本在隔离 namespace 执行；返回 dict 时透传 `lines`/`markers`（支持多线指标）

**指标脚本编写规范**（详见 API文档 §9）：
- 入口 `main(params, ohlcv)`；单线返回 `[null|num,...]`，多线返回 `{"lines":[{name,type,values,style}]}`
- 可选元数据：`PARAMS={默认值}`（自动命名+弹窗回显）、`NAME`（根名）、`label(params)`（自定义显示名）
- 柱状图 `type:"histogram"` 默认涨跌自动红绿；style `autoColor:false` 时用 `color` 固定单色
- 多线绘制层级=创建顺序：柱先线后（`zOrdered`），避免柱遮线
- 参数化是核心：同一脚本靠不同 `params`+`indicator_name` 复用（如 sma7/sma20），改参数走 update 接口自动重算+自动改名

### 4.3 core/datasource.py — DataSourceManager
- 轮询任务（asyncio）；`set_config` 记录配置（一次性也记录，供历史回溯）
- **K 线合并**（`_merge_ohlcv`）：保留比新窗口更早的历史 + 新窗口，实时轮询不冲掉已加载历史
- 连续 3 次失败 → 推 `datasource_error`

### 4.4 core/service.py — AgentKlineService
- 所有业务操作（画板/周期/K线/指标/副图/数据源/历史/状态）
- 操作成功后调 `self.notify(msg)` 发推送事件
- `refresh_dynamic_indicators`：K 线变化后重算所有"动态指标"（run-script 添加的脚本指标）

## 5. 关键数据流

### 5.1 实时刷新（轮询）
```
datasource 轮询 → run_script → _merge_ohlcv(保留历史) → set_ohlcv
  → refresh_dynamic_indicators(重算脚本指标)
  → notify(ohlcv_update / indicator_refresh) → WS → 前端原地更新
```

### 5.2 历史回溯（向左平移）
```
前端视口 from<=2(用户手动) → POST /history → run_script(until=earliest)
  → 前插 older → notify(ohlcv_update, prepended=N)
  → 前端视口右移 N，保持看到原K线
```

### 5.3 前端原地更新（不重置视口）
- 实时更新不重建图表，只 `series.setData` 更新数据
- 视口策略：在右缘→跟随新K线；缩放/左移中→保持视口；历史前插→右移 N

## 6. 前端设计（Vite 模块化，v0.3 已完成工程化）

前端源码在 `frontend/src/`，Vite 构建到 `web_dist/`，由 FastAPI 服务（`/` + `/assets`）。
**无回退**：未构建时 `/` 返回 503 提示先 `npm run build`。模块划分（依赖无环）：

| 模块 | 职责 |
|------|------|
| `lwc.js` | `import * as LightweightCharts`（npm v5.0.0）再导出 |
| `state.js` | 全局 `state` 对象 |
| `format.js` | `formatTimeCN` / `isIntraday` |
| `log.js` | 日志、`toggleLog` |
| `ui.js` | 画板/周期 tab、切换（只 fetch，渲染靠 WS 触发） |
| `render.js` | 建图/指标/划线/成交量/时间+十字标同步/视图上报 |
| `ws.js` | WebSocket、消息分发、`applyState` |
| `main.js` | 入口：绑定事件 + 连接 WS |

依赖方向：`state/format/lwc/log ← ui ← render ← ws ← main`。

构建：`cd frontend && npm install && npm run build`。
（注意：构建依赖 devDependencies，请勿在 install 时设置 `NODE_ENV=production`；
网络受限时可临时指定镜像 `--registry=https://registry.npmmirror.com`。）

关键机制（与单文件版一致，仅组织变化）：

| 机制 | 实现 |
|------|------|
| 时间轴联动 | `subscribeVisibleLogicalRangeChange` 互相同步主副图 |
| 十字光标联动 | `subscribeCrosshairMove` + `setCrosshairPosition`（垂直同时刻，水平各自值） |
| 实时不重置 | `applyDataUpdate` 原地更新 + 视口保持/跟随 |
| 历史加载 | 视口左缘(用户手动)触发 `loadMoreHistory`；程序化视口打标不触发 |
| 默认视口 | `showLatest(200)` 右对齐最新 200 根，非全量 |
| 指标显隐 | 指标栏 chip 点击 toggle；副图全隐藏→折叠释放空间 |
| 指标无杂线 | 指标 `priceLineVisible/lastValueVisible/crosshairMarkerVisible=false` |
| 图例 | 主图 OHLC+涨跌 / 成交量 / 副图指标，**一个指标一行**（行内多值横排），行数超限（主6/副2/量1）回退横排；随十字标更新，移开显示最新；`updateLegends()` |
| 指标层级 | `zOrdered()` 柱状先创建（垫底）、线/面积后创建（在上），防 MACD 柱遮线 |
| 指标命名 | 内部 `name` 稳定 + `display_name` 自动「根名(参数)」/可覆盖；根名优先级：run-script `display_name` > 脚本 `label()` > 脚本 `NAME` > 文件名 stem；脚本声明 `PARAMS` 默认值（合并存储，供命名+弹窗回显）；`_auto_display`/`_set_display` |
| 指标更新 | `POST /api/indicator/update/{name}`：`params`→重算、`style`→单线、`lines_style`→逐线、`display_name`→自定义、`auto_label`→恢复自动；前端 chip ⚙ 设置弹窗 |
| 时间格式 | 中国习惯；日线只显示日期，日内显示日期+时间 |
| 去 logo | `layout.attributionLogo=false` |
| 用户划线 | 左侧工具栏 水平线/趋势线；两点锚点+虚线预览；双击选中/拖动/端点/右键菜单；`draw_interact.js`；划线为图表原生对象（可被截图） |
| 划线默认样式 | 每工具默认(color/lineStyle/lineWidth)存 localStorage；预览辅助线继承默认；改样式保存后成为该类型新默认（TV 式） |
| 最新价标签 | 自绘 `.last-price-label` 始终显示最新收盘(涨绿跌红)，越界吸附价格轴顶▲/底▼；`updateLastPriceLabel()`，渲染/视口/数据更新后 + rAF 复核 |
| 截图 | `captureSnapshot()` 用 takeScreenshot 拼接 主图+成交量+副图；`drawOverlay()` 把 DOM 图例(OHLC/指标值/VOL)+最新价标签画回 canvas；WS `snapshot_request` 触发，上传 `/api/snapshot` |
| 标记单位 | markers time 统一毫秒；`<1e11` 视为秒自动×1000（容错） |

**注意**：Lightweight Charts **不自带画图工具**，本项目用自绘叠加层+原生 series 实现画线。

### 前端工程化（已完成 v0.3）
已从单文件迁移到 Vite + 模块化原生 JS（见上），旧单文件 `static/board.html` 已删除。
框架（Vue/React）明确推迟，
待 UI 状态复杂化（大量面板/表单/路由）时再引入；届时只需重写 `ui.js` 层，

## 8. MCP 设计

- 用 `mcp.server.fastmcp.FastMCP`，工具一一映射 service 方法
- **Streamable HTTP 挂载**：`api/agent_app.py` 把 `mcp` 挂到 agent 端口 `/mcp`，
  与 web 端口共享同一 service 实例（`mcp_server.service = service`），agent 操作实时推 WS
- 不再提供独立 stdio 进程（无头实例与"共用画板"目标相悖）；如后续需兼容仅 stdio
  的客户端，可再加指向本服务的 HTTP 薄代理
- 工具粒度：画板/周期/数据源/脚本/指标(含 `update_indicator`)/副图/标记/划线/状态/
  截图(`take_snapshot`/`get_snapshot`)，覆盖 AI 自动化全流程
- 截图依赖浏览器连接 `/ws`（后端不渲染）；`take_snapshot` 发 `snapshot_request`
  后轮询读取，合成图含图例+最新价标签
- 鉴权：agent 端口（含 `/mcp`）全量需 Bearer token，读+执行不区分（见 API文档 §12）；
  时间单位统一毫秒

## 9. 部署

```bash
./start.sh                 # 或 pip 安装后: agentkline
# web  : http://<host>:8765        （用户浏览器，无鉴权）
# agent: http://<host>:8766/mcp/   （AI agent，全量鉴权）
```

双端口 host/port 在 config.yaml `server.web` / `server.agent` 配置，或被
`AGENTKLINE_WEB_HOST/PORT`、`AGENTKLINE_AGENT_HOST/PORT` 覆盖。
鉴权（可选）：`AGENTKLINE_TOKEN` 或 `config.yaml auth.token`；不设置则 agent 端口仅本机可用。

路由分组（`routes.py`）：
- `register_read` 只读（两端口都有）
- `register_user_write` 用户交互写（仅 web）
- `register_manage` 删板 / 删周期 / 删改指标（**两端口都有**）
- `register_exec` 执行 / 脚本 / 数据源（仅 agent，全量鉴权）

端到端测试（打 agent 端口，需 token）：

```bash
python test_e2e.py --port 8766 --token <token>   # token 也可用环境变量 AGENTKLINE_TOKEN
```

依赖：fastapi / uvicorn / pydantic / websockets / mcp / ccxt / pyyaml（见 requirements.txt / pyproject）。
