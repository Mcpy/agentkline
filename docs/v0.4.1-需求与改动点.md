## 1. CAPS.ticker 契约（脚本层）

- 数据源可声明 `CAPS={"ticker": True}` ⇒ 必须实现 `ticker(params) -> dict`：
  `{price: float, ts: ms, change_pct: float|None, extra: {...}|None}`（键白名单校验）。
- save_script 静态校验族扩展：`ticker=True` 无 `ticker` 函数 ⇒ `CAPS_MISMATCH`（与 backfill/symbols 同门）。
- builtin 落地：`ccxt_binance` 增 `ticker()`（fetch_ticker 窄字段）；`mock_btc` 增合成 ticker（供 e2e/演示）；csv= False。
- 单粒度/离线源老实声明 False（契约义务同 INTERVALS）。

## 2. WatchlistManager（core/watchlist.py，新模块）

**结构**
```python
groups = [ {id, name, rows: [ {source, identity, symbol_display} ]} ]   # 0.4.1 仅默认组 "default"
quotes = { row_key: {price, change_pct, ts, state} }                    # row_key = source|symbol
```
- `add_row(source, symbol)`：校验源存在且 CAPS.ticker（无⇒`TICKER_UNSUPPORTED` 400 带支持说明）；
  幂等（同二元组重复加=ok）；`remove_row`、`list_watchlist`（带每行 state+现场徽标 has_board）。
- **三态分发**（每 tick 对每行判定）：
  - `visible`：存在锁定板且 = 用户当前板（current_view.board 匹配 identity）→ 发 `quote` 事件带 board_id，
    前端即时刷 data-info/最新价标签（补 K线轮询间隙的"心跳价"）；
  - `hidden`：有锁定板但非当前 → quotes 缓存 + 行上"·N"未读心跳计数（切板时清零）；
  - `watch`：无板 → 仅面板展示。
- **轮询**：单 ticker poller（默认 `quotes_poll_s=5`，config 可调）；行内并发=ThreadPool(min(rows,8))；
  单行失败不炸整轮（行级 error 计数，连续 10 次失败 → 行标 stale 不删）。
- 与 boards 联动：delete_board 不删 watch 行（雷达独立于现场）；建板不自动加雷达（用户显式加，见 §4 入口）。

## 3. 防漂移①：统一注册装饰器（interface/registry.py，新模块）

**单一源**：一个函数 + 一个装饰器同时产出 REST 路由（双端口按组）与 MCP 工具：
```python
@api_tool(group="user_write", mcp=True, web=True)
def add_indicator(board_id: str, timeframe: str, ...) -> dict: ...
```
- 组策略表集中声明：`GROUP_PORTS = {read: [web, agent], user_write: [web, agent], manage: [agent], exec: [agent]}`
  （web 写端点=登录挂载面承诺不变）。
- MCP 侧：FastMCP 从函数签名+docstring 生成 schema（现状 docstring 已是参数说明风格，迁移成本低）；
  REST 侧：FastAPI 从同签名生成 query/body 模型（简单标量=query，dict/list=body，沿用现约定）。
- 迁移策略：**一次性全迁**（~45 端点/35 工具），e2e 两表面对齐断言全程当安全网；迁移完删
  routes.py 手工镜像与 mcp_server.py 手工 wrapper（mcp_server 仅留 service 绑定+快照特例）。
- 风险与回退：装饰器 schema 推断覆盖不了的特例（snapshot 二进制返回、SSE）保留手工出口并注释豁免清单。

## 4. 接口面（装饰器新风格首用=雷达端点）

| REST | MCP 工具 | 说明 |
|---|---|---|
| GET /api/watchlist | watchlist_list | 组+行+quotes 快照+state+has_board |

| DELETE /api/watchlist/rows | watchlist_remove | 同参 |

`watchlist_changed`（增删广播）。

## 5. 前端（watchlist.js 新模块 + 入口）

- **雷达抽屉**：右侧滑出面板（工具栏"雷达"按钮切换，宽度 280px，不挤主图）；
  行= `源stem: 符号` + 最新价 + 涨跌幅(红绿) + ●现场徽标 + state 点（visible 绿/hidden 灰/watch 蓝）；
  hidden 行未读心跳计数角标。
- **行点击语义**：有板 → switch_board 切现场；无板 → **一步建板即锁**（复用搜索流建板函数，免再搜）。
- **加入雷达入口**（两处，均显式）：搜索弹层每行"＋盯"次按钮；板标签右键菜单"加入雷达"。
- 面板数据纯 WS 驱动（quotes_update/watchlist_changed），无轮询 fetch。

## 6. e2e 增补（52 → ~62 断言）

- mock ticker 源自给（save_script CAPS.ticker + ticker 函数）；CAPS ticker 声明无函数⇒CAPS_MISMATCH；
- 无 ticker 源加雷达⇒TICKER_UNSUPPORTED；增删幂等；三态判定（建板/切板/删板各态迁移）；

- 装饰器迁移回归：全端点两表面对齐断言保持全绿（迁移安全网）。

## 8. 顺序与验收（DoD）

1. 装饰器①全迁 + e2e 全绿（安全网先立）；
2. CAPS.ticker + builtin ticker 落地 + 校验门；

**待拍板**：① 雷达抽屉位置（右抽屉 vs 底部栏）——我推荐右抽屉（竖列表信息密度高、不压 K 线纵轴）；
② 无板行点击=一步建板即锁（推荐，与搜索流同语义）vs 跳搜索预填；
③ 装饰器一次性全迁（推荐，e2e 兜底）vs 增量双轨；
④ quotes_poll_s 默认 5s（与 K线轮询同频，推荐）vs 更激进的 2s。
