# AgentKline 引擎插件开发指南（v0.6.1）

本文写给要接一个新回测引擎的人（包括未来的 backtrader / 事件式引擎移植）。
内置 `builtin` 引擎也是按同一份协议实现的——没有特殊通道。

## 1. 两个包、两个命令

```
agentkline（主包）            后端 + builtin 引擎 + 前端产物
   └─ 依赖 ──> agentkline-engine-core（框架：契约/撮合/统计/ak-engine 命令）
```

| 命令 | 来自 | 用途 |
|---|---|---|
| `agentkline` | 主包 | 起双端口服务（web 8765 / agent 8766 + `/mcp`） |
| `ak-engine` | core | `list` / `run --stdin` / `validate-strategy`，跑完就退出 |

- 内置引擎**不需要单独安装**：装主包会自动带上 core，`builtin` 在主包里注册 entry point。
- 第三方引擎**单独成包**，只依赖 `agentkline-engine-core`，不拖 FastAPI/uvicorn。
- 源码安装（一个仓库两个 distribution）：

```bash
pip install -e . -e engine/core
ak-engine list --json          # 应看到 builtin
```

## 2. Engine 协议

```python
class Engine(Protocol):
    id: str            # 唯一 id，后端按它选引擎
    version: str       # 你的包版本
    api: int           # 必须 == agentkline_engine.contract.ENGINE_API（当前 1）
    caps: dict         # 能力声明
    assumptions: dict  # 执行假设（结果里展示/对比）
    def run(self, req: RunRequest) -> RunResult: ...
```

### caps（能力声明）

| 键 | 含义 |
|---|---|
| `signal` | 接受 `target` 权重数组（signal 策略） |
| `event` | 事件式（`initialize/handle_data`，预留） |
| `short` | 支持做空 |
| `leverage` | 支持杠杆 |
| `multi_symbol` | 支持多标的 |
| `protection` | 支持 entry 级止损/止盈 |

后端只按 caps 渲染/放行能力；`false` 的项会被禁用。

### assumptions（结果里的执行假设）

固定键见 `agentkline_engine.contract.DEFAULT_ASSUMPTIONS`：
`fill_rule / bar_close_policy / lot_policy / direction / shorting / leverage / fee_bps / slippage_bps /
funding_mode / calendar / corporate_actions / bars_per_year / annualization / protection_rule / intrabar_mode`。
跨引擎对比就是逐字段比这些，别自造同义键。

## 3. 注册与发现

```toml
# 你的 pyproject.toml
[project.entry-points."agentkline.engines"]
myengine = "my_pkg.engine:MyEngine"
```

- `ak-engine list --json` 通过 entry point group `agentkline.engines` 发现；坏插件只记 `load_error`，不影响其他引擎。
- 装进同一个 venv 即可；后端无需改代码、无需重启（清单每次子进程现查，结果有缓存）。
- `api != 1` 会被拒：`API_MISMATCH`。

## 4. 运行协议（子进程边界）

后端**不 import 你的引擎**，只跑：

```bash
ak-engine run --stdin   # spec 从 stdin 读；结果从 stdout 出
```

- stdin：`{"api":1, "engine":"myengine", "bars":[...], "strategy":{"source":"..."}|{"path":"..."},
  "run":{...}, "timeframe":"1d"}`；
- stdout：第一行哨兵 `__AK_RESULT__`，紧随其后一行结果 JSON；
- stderr：日志与用户 `print`（后端只取尾部 4KB 进错误详情）；
- 不落盘：bars/策略源码/结果全程走管道；
- 超时：后端 `killpg` 整组（你 fork 的子进程也会被杀）；
- 退出码：`0` 成功、`2` 输入/契约、`3` 崩溃、`4` 超时、`5` 引擎内部错误；出错时同样输出哨兵 +
  `{"error":{"code","message","detail"}}`。

所以你的引擎要保证：

1. **可被独立运行**（不依赖后端进程内的任何对象）；
2. 崩溃只影响自己（不要 try 住 `os._exit`/段错误——那正是子进程要隔离的）；
3. 不写临时文件（大数组走内存；5 万根也要能跑）。

## 5. 复用 core 的零件（推荐）

```python
from agentkline_engine.contract import RunRequest, RunResult, DEFAULT_ASSUMPTIONS
from agentkline_engine.bars import load_bars
from agentkline_engine.loader import load_strategy
from agentkline_engine.matching import MatchingEngine
from agentkline_engine.metrics import compute_stats_full
from agentkline_engine.result import build_result
```

- `load_strategy(req.strategy_source)`：解析声明 + 返回 `main`（signal 契约）；
- `MatchingEngine(initial_cash, fee_bps, slippage_bps, rebalance_tolerance)`：
  `execute_target(bar, target, equity, reason)` / `check_protection(bar, protection)` /
  `force_close(bar)` / `equity(price)`；
- `compute_stats_full(times, values, trades, initial_cash, bpy, fills=fills)`：与 0.6.0 口径一致；
- `build_result(...)`：装配 `schema=1` 的 `RunResult` 并做自检。

**想复用 signal 内核**（自己只换撮合/费用模型）：直接调
`agentkline_engine.drivers.signal.run_signal(req, strategy, self)`，再覆盖你要改的部分。

## 6. 结果必须长这样（schema=1）

```json
{
  "schema": 1,
  "engine": {"id": "myengine", "version": "0.1.0", "api": 1, "caps": {}, "assumptions": {}},
  "status": "completed_trades",
  "bars": {"count": 2200, "from": 1602547200000, "to": 1792540800000, "timeframe": "1d"},
  "fills": [{"id": "f1", "time": 1602547200000, "action": "buy", "signed_qty": 0.1,
             "price": 10000.0, "notional": 1000.0, "fee": 0.5, "reason": "signal"}],
  "trades": [{"id": "t1", "side": "long", "entry_time": 0, "exit_time": 0,
              "entry_price": 0, "exit_price": 0, "size": 0, "notional": 0,
              "gross_pnl": 0, "fee": 0, "pnl": 0, "pnl_pct": 0,
              "entry_reason": "", "exit_reason": "", "holding_bars": 0}],
  "equity": {"times": [1602547200000], "values": [10000.0]},
  "stats": {},
  "warnings": [],
  "assumptions": {}
}
```

- `status` ∈ `no_signals | open_position_only | completed_trades`；
- 后端会：校验 schema/长度、补 `result_id/board/timeframe/units/created_at`、**按同一口径重算 stats**、
  记录数据质量与可复现指纹，然后广播 `result_created`；
- 所以：`stats` 可以留空（后端会算），但 `equity`/`trades`/`fills` 的字段名要对齐；
- 额外指标放 `engine.extra_metrics`，不要覆盖标准字段。

## 7. 验证清单

1. `ak-engine list --json` 能看到你的 id，`api=1`；
2. `ak-engine run --spec` 能跑出 `schema=1`（参考 `engine/examples/run.json`）；
3. 同一份 bars + target，与 `builtin` 逐数对比：fill 笔数/时间/价格、逐 bar 权益；
4. 崩溃隔离：`os._exit(7)` / 段错误 → 后端拿到 `ENGINE_CRASH`，服务不重启；
5. 超时：sleep 超过 `timeout` → `RUN_TIMEOUT`，进程组被 kill；
6. 5 万根 1d 单策略 < 3s（本机基线）。

与 `builtin` 对齐时可以把 `engine/alignment/compare.py` 当模板（内部对标工具，不随发布）。

## 8. 打包

- 包名 `agentkline-engine-<name>`，依赖 `agentkline-engine-core>=0.1,<1`；
- 只 import `agentkline_engine`，不要 import `agentkline`（主包）——否则子进程会拖进 FastAPI；
- 版本独立演进；结果里的 `engine.version` 用你自己包的版本；
- 许可证：移植第三方框架（如 backtrader，GPL-3.0）时单独成包、单独声明，不进主包。

## 9. 最小骨架

见 `engine/examples/plugin_engine.py`（`MyEngine` 的 caps/assumptions/run 骨架 + 注册说明）。
复制到你的包里，实现 `run()` 即可；运行 `ak-engine list` 验证注册。
