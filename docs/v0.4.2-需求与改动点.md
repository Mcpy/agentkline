# AgentKline v0.4.2 需求与改动点（施工单 · 规划态→已拍板）

> 状态：**已拍板开工**（2026-09-27）。主题：**雷达分组 UI + 旧账清偿 + 打磨**。
> 三个决策点按推荐落：①删组=行回落默认组（不级联删）②拖拽排序/移组做 ③hover 高/低/量卡做。
> 数据结构零重构承诺兑现：服务端 `groups[]→rows[]` 0.4.1 第一天已铺，本版长出 UI 与管理面。

---

## A. 雷达分组（主特性）

### A1. 服务端（core/watchlist.py）
- `groups[]` 现为单默认组；增组管理：
  - `add_group(name)` → `{id, name}`；重名 `GROUP_EXISTS`(400)
  - `rename_group(group_id, name)`；默认组不可改名/删（`GROUP_PROTECTED`）
  - `remove_group(group_id)` → **行回落默认组**（不级联删行）
  - `move_row(source, symbol, to_group_id, index?)` → 移组+定位（排序）
  - `add_row(..., group_id=None)` 扩参：加行时指定组（默认=default）
  - 行序持久于 groups[].rows 列表序（内存态，0.5 随 watchlist 落盘）
- `list_watchlist()` 返回形状不变（groups[]→rows[] 本就带组信息），补 `group.name`；
- WS：复用 `watchlist_changed`（全量结构），前端重渲染分组。

### A2. 接口面（api/tools.py 单一注册源，@api_tool）
- 新工具 4 枚（MCP 39→**43**）：
  - `watchlist_group_add(name)` / `watchlist_group_rename(group_id, name)` / `watchlist_group_remove(group_id)`
  - `watchlist_move(source, symbol, group_id, index=None)`
- `watchlist_add` 扩 `group_id` 可选参（向后兼容：不传=default）；
- REST 双端口路由随装饰器自动生成（user_write 组）。

### A3. 前端（抽屉面板）
- **分组呈现**：面板按组分节；组头=名称+行数+折叠箭头（折叠态存 localStorage）；
- **组管理**：面板头"＋"=新建组（inline 输入）；组头右键/悬停菜单=重命名、删除（删除确认文案注明"行回落默认组"）；
- **行归属**：搜索弹层"＋盯"与面板加行入口带组选择（默认 default；多组时弹小菜单）；行右键菜单加"移到组→"子菜单；
- **拖拽**：行 draggable，组内排序 + 跨组投放（HTML5 DnD，投放位指示线）；落定调 `watchlist_move`；
- 三态点/现场徽标/价格红绿等 0.4.1 行为全保留，仅套进分节容器。

## B. 旧账清偿
- **take_snapshot allow_stale**：默认 fail-loud 不变（NO_BROWSER）；`allow_stale=true` 时返回最近磁盘快照 + `stale: true` + 文件时间戳；MCP 描述同步；
- **面板内过滤**：抽屉头小搜索框，实时过滤行（symbol/源名/display 模糊，大小写不敏感）；过滤态下隐藏空组头。

## C. 打磨
- **WS 重连韧性**：走查 ws.js 重连路径；重连成功后主动拉 `watchlist_list` + `get_quotes` 刷新面板（防断线期间增删/价格丢失）；
- **hover extra 卡**：行 hover 浮出小卡（24h 高/低/量，数据在 quote.extra，白捡）；无 extra 则不显示；
- **文档级联**：API 文档雷达节补分组、script skill 不变、ai-walkthrough 补分组意识、附录重生成、施工单 as-built。

## D. 非目标（排队不变）
持久化/登录→0.5；L2/回测→0.5+；性能不再加码（0.4.1 四优化已达标，等真实反馈）。

## F. 老 bug1 回归剿灭（2026-09-27 用户报「删板后 K 线还在」）

**双根因（v0.4.1 起潜伏，两条兜底路径同刻断）**：
1. `ui.js deleteBoard` 删光路径调 `renderChart()` 但**漏 import**（ui.js 只 import openIdCard）→ ReferenceError 断乐观路径；
2. `ws.js board_remove/board_create` handler 首行调 `refreshSearch()` 但**漏 import**（refreshSearch 在 search.js）→ ReferenceError 断 WS 广播兜底路径（v0.4.1 加 refreshSearch 调用时漏带 import；v0.4.0 时该调用不存在故未暴露）。

**取证链**：截图特征（tabs 空+data-info 旧值+canvas 残留）→ 静态 grep 定根因 1 → RX 探针证消息到达 → handler 探针抓 `refreshSearch is not defined` 定根因 2 → 服务端 BC 探针证广播已发（排除发送侧）。

**修复**：两行 import 补齐（ui.js renderChart / ws.js refreshSearch，均无环）；探针验完清零。
**验证**：guest 浏览器建板→删板→guide 落页/tabs 0/canvas 0/data-info 0 bars/board_remove 业务行齐全；e2e 85/85；探针零残留。
**教训记账**：handler 首行旁路调用（refreshSearch 这类"顺手刷新"）是静默断链高发位——0.4.2 起 e2e 已有两表面对齐，但前端 import 断链只能靠活体；建议 0.4.3 护栏加前端构建期 lint（未定义标识符检测，esbuild 已报未用 import 但不报未定义全局）。
