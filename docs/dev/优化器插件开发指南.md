# 优化器插件开发指南（v0.6.6；v0.6.7 补稳健性边界）

参数寻优的“搜索算法”是一个脚本插件，和数据源 / 指标 / 策略同属脚本体系。

> v0.6.7 补充：walk-forward 与参数邻域由**内核**编排，不属于优化器脚本契约。
> 优化器仍只看到当前折/当前窗口的 `ctx.history` 与空间；不要在脚本里切数据、
> 跑 OOS 或保存报告。每折会重新调用 `init`，脚本不要跨折缓存状态。

## 1. 放在哪里

| 来源 | 目录 | 说明 |
|---|---|---|
| 内置 | `agentkline/resources/scripts/optimizer/` | 随包发布，只读；grid / random / bayes |
| 自定义 | `scripts/optimizer/`（`scripts.dir` 可改） | 用户 / AI 写入；同名 shadow 内置 |

id = `optimizer/文件名`，例如 `optimizer/grid`。`GET /api/optimizers` 或 MCP
`list_optimizers` 返回 `id/name/source/params/param_meta/caps/api`。

## 2. 最小契约

```python
OPTIMIZER_API = 1
NAME = "我的优化器"
DESC = "一句话说明"
PARAMS = {}                 # 优化器自己的参数，字面 dict
PARAM_META = {}             # 参数类型/范围，字面 dict
CAPS = {"continuous": False, "multi_objective": False,
        "requires_full_space": False, "custom_score": False}

def ask(state, ctx):
    """返回下一组策略参数 dict；None = 搜索结束。"""
    ...
```

保存时只做 AST 校验（不执行）：必须有 `OPTIMIZER_API=1` 和 `ask`，`PARAMS/PARAM_META/CAPS`
必须是字面量。缺 `ask` 报 `SAVE_OPTIMIZER_ASK`，缺 API 报 `SAVE_OPTIMIZER_API`。

## 3. 可选钩子

```python
def init(ctx):
    """每个作业调用一次；返回本作业 state（建议 JSON 可序列化）。"""
    return {}

def tell(state, ctx, trial):
    """每组试次跑完后回调；trial 含 params/status/score/value/is_stats。"""

def rank(state, ctx, trials, phase):
    """自定义 Top K 排序；phase = 'is' | 'oos'；返回 trial 下标列表，None=回落标量分。"""
    return None

def summarize(state, ctx):
    """报告附加字段（如 Pareto front、种群收敛）；返回 dict。"""
    return {}
```

## 4. ctx 里有什么

```python
ctx = {
  "space": {
    "raw": {...},          # 请求里的原始 space
    "values": {"fast": [5, 10], ...},  # 离散候选值（range 已展开）
    "base": {"fast": 10, ...},         # 策略默认参数
    "meta": {"fast": {"type": "int", "min": 2, "max": 200}, ...},
    "size": 4,             # 离散空间总组合数
  },
  "objective": {...},      # 单目标：{metric,direction}；多目标：自由结构
  "constraints": {"min_trades": 10, "max_drawdown": 0.4},
  "budget": {"max_runs": 40, "max_seconds": 600},
  "seed": 42,
  "params": {...},         # 优化器自己 PARAMS 的生效值
  "history": [trial...],   # 已跑试次（只读副本）
  "done": 12, "elapsed_ms": 8123,
  "rng": random.Random(...)  # 每作业独立、按 seed 可复现
}
```

试次 `trial` 的关键字段：`index/params/status/score/value/reason/is_stats`；样本外补
`oos_status/oos_score/oos_value/oos_stats/overfit_*`。

## 5. 内核负责什么

优化器只负责“提议 + 可选排序”。以下留在内核，插件不要重复实现：

- 参数空间校验（`PARAM_META` 类型/范围）、候选值校验；
- 跑回测、单组异常隔离；
- 预算（`max_runs/max_seconds`）、取消；
- 样本内/外切分、Top K 的样本外验证；
- 结果登记、报告、广播。

候选可以不在 `space.values` 里（只要在 `PARAM_META` 范围内），这是给连续空间 / GA / PSO
留的口子；`CAPS.continuous=True` 时进度总数按 `max_runs` 计。

## 6. caps

| cap | 含义 |
|---|---|
| `continuous` | 候选可不在离散候选列表里；总数按预算 |
| `multi_objective` | `objective` 允许自由结构；内核不强行解析单指标 |
| `requires_full_space` | 空间组合数超过预算直接拒绝（grid 用） |
| `custom_score` | 预留：脚本可提供自定义评分（当前由 `rank` 覆盖排序即可） |

## 7. 多目标 / Pareto

`CAPS.multi_objective=True` 时：

- 请求的 `objective` 原样传给 `ctx["objective"]`，可以是 `{"metrics":[...]}` 或权重结构；
- 内核只做约束判定，不生成单指标 `score`（试次 `score=None`）；
- `rank(state, ctx, trials, phase)` 用 `trial["is_stats"]` / `trial["oos_stats"]` 自己排序；
- 返回的下标顺序就是 Top K 顺序；报告 `ranked_by="optimizer"`；
- `summarize` 可把 Pareto front 放进 `report.extra`。

多目标不作为内置优化器发布；上面是接口可行性验证路径。

## 8. 优化器参数

`PARAMS` / `PARAM_META` 与策略参数同构；UI 会在“搜索方法”下面渲染“优化器设置”，
请求里用 `optimizer_params` 覆盖默认值。例如遗传算法：

```python
PARAMS = {"population": 20, "mutation": 0.1}
PARAM_META = {
    "population": {"type": "int", "min": 5, "max": 200, "label": "种群"},
    "mutation": {"type": "float", "min": 0, "max": 1, "label": "变异率"},
}
```

服务会按 `PARAM_META` 校验，未知参数报 `OPTIMIZER_PARAM_INVALID`。

## 9. 安全与边界

- 与指标/策略脚本同一套 L1 执行模型：同进程 `exec`，不是安全沙箱；不要执行不可信代码；
- `ask` 内不要做长时间阻塞；超时只在两组之间检查；
- 模块级可变变量不保证跨作业隔离；跨调用状态放 `state`；
- 插件异常会让作业 `failed`，错误码 `OPTIMIZER_ASK_FAILED/INIT_FAILED/TELL_FAILED`；
- 非法候选记一行 `invalid`，扣预算但不炸作业。

## 10. 参考实现

- `optimizer/grid`：全组合，`requires_full_space=True`；
- `optimizer/random`：离散均匀采样 + 去重；
- `optimizer/bayes`：复用 `agentkline.core.optimizer.propose_tpe` 的 TPE-lite。

更多搜索算法（GA/PSO/加权/Pareto）应作为 `scripts/optimizer/` 自定义脚本接入，不改内核。
